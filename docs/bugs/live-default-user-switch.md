# 既定ユーザー変更が現在の画面に反映されない不具合

## v0.2.5での再現

1. 登録済みのone（OLD001）で画面を開き、授業情報を表示する。
2. Uでユーザー管理を開き、two（NEW002）へカーソルを動かす。
3. Dで確認画面を開き、Enterで既定に設定する。
4. 設定ファイルと画面内の状態を比較する。

実際のキー処理・設定保存を使い、Keychainだけを模擬した隔離環境で再現した。大学には接続していない。表示名・番号はテスト用で、実際の個人情報ではない。

| 状態 | 修正前 | 修正後 |
| --- | --- | --- |
| 保存された既定ユーザー | two | two |
| 画面の学籍番号 | OLD001 | NEW002 |
| 旧ユーザーのパスワードを使用中 | はい | いいえ |
| 現在の選択 | OLD001 | NEW002 |
| 保存済みのGUI選択 | OLD001 | NEW002 |
| 前のユーザーの授業情報 | 残る | 破棄する |

修正前の回帰テストでは、設定がtwoへ保存されたことを確認した直後に、画面の学籍番号がNEW002になるという検証が `OLD001 != NEW002` で失敗した。修正後は同じ検証が成功する。

実際のcurses画面もPTYで操作し、旧v0.2.5と修正版に同じ `U → ↓ → D → Enter` を入力して比較した。両方とも既定は「ゲスト」へ変わるが、旧版の実行ユーザーはDEMO001のまま、修正版はDEMO002へ即時に切り替わった。どちらもデモを使い、設定ファイルと実Keychainには保存していない。

## 原因と変更

既定変更は設定ファイルだけを書き換え、現在のユーザー・パスワード・選択状態を更新していなかった。授業情報の破棄と再確認も通常の選択切替にしか実装されていなかった。v0.2.5ではGUIの選択を保存・復元するため、旧ユーザーの保存済み選択が再起動後にも優先される場合がある。

GUIからの既定変更では、対象の保存パスワードを先に取得し、既定とGUI選択を1回の設定保存で変更する。成功したイベントを受けて現在の認証情報と選択を入れ替え、古い授業・出席済み状態を破棄する。QR入力済みなら確認のみで授業情報を取り直し、登録は利用者の明示操作を待つ。

確認画面には、現在の出席対象も選んだ1人へ切り替えることを表示する。通常の複数選択やCLIの既定変更の操作は維持する。別プロセスからの設定変更を監視する変更ではなく、同じ画面のU → D → Enterへの対応である。

## 検証

`tests/test_live_default_user.py` で、実キー処理、認証情報と選択の更新、再起動時の復元、QR入力済みの再確認、複数選択からの切替、取得・保存失敗時の不変性、キャンセル、デモ、最小幅を含む画面表示を検証する。

```sh
.venv/bin/python -m unittest discover -s tests -p test_live_default_user.py
```
