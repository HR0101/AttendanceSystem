# v0.2.8

## 変更内容

- 通常起動の更新確認をバックグラウンドで実行し、GitHubやDNSの応答待ちで出席操作の開始・終了を遅らせないようにしました。
- 成功した更新情報は原則24時間再利用します。通信失敗時や利用制限時は従来の再試行間隔を維持します。
- UIを開く直前の通知出力をやめ、起動後に確認が完了した場合も画面内の更新案内へ反映します。
- CLIの入力中には通知を割り込ませず、起動時の保存済み情報と処理終了時に取得済みの新情報を案内します。
- スケジュール削除の確認画面で「キャンセル」を初期選択とし、授業名・曜日・開始時刻・登録時刻・QR番号を確認して `Tab` / `←→` で「削除する」を選んだときだけ削除するようにしました。
- ユーザー管理や予定の入力フォームで途中の項目からも `Ctrl+S` で保存でき（画面実行中のみ端末のフロー制御を一時解除して終了時に復元）、パスワード入力欄の表示切替に `F2` に加えて `Ctrl+T` を使えるようにしました。
- ユーザー管理のサブ画面における `Esc` 戻り先と失敗時の入力保持を見直し、出席確認・登録の通信中でも `Esc` / `Q` / `Ctrl+C` で安全に中断要求できるようにしました。

## 利用者の操作

- `att update` で更新し、画面を開き直してください。
- 更新案内が出た場合は `att update --notes` で内容を確認し、`att update` で更新してください。手動コマンドはキャッシュの期限内でも最新情報を取得します。
- 更新確認を無効にする場合は、引き続き `ATTENDANCE_NO_UPDATE=1 att --ui` を使えます。通常起動ではアプリ本体や依存パッケージの自動更新は行いません。
- スケジュールを削除するときは、`D` の確認画面で対象授業を確認し、`Tab` / `←→` で `[ 削除する ]` を選んで `Enter` を押してください（`Enter` 連打や `Esc` / `Q` では削除されません）。
- 入力フォームを途中から保存したいときは `Ctrl+S` を、Mac 等でパスワード表示を切り替えたいときは `F2` または `Ctrl+T` を、通信処理を止めたいときは `Esc` / `Q` / `Ctrl+C` を利用してください。
