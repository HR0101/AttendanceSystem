# v0.2.8

## 変更内容

- 通常起動の更新確認をバックグラウンドで実行し、GitHubやDNSの応答待ちで出席操作の開始・終了を遅らせないようにしました。
- 成功した更新情報は原則24時間再利用します。通信失敗時や利用制限時は従来の再試行間隔を維持します。
- UIを開く直前の通知出力をやめ、起動後に確認が完了した場合も画面内の更新案内へ反映します。
- CLIの入力中には通知を割り込ませず、起動時の保存済み情報と処理終了時に取得済みの新情報を案内します。
- `install.sh` とCIの依存パッケージ導入で非ハッシュ導入（`requirements.txt` フォールバック）を廃止し、wheel限定（`--only-binary=:all:`）と監査用ロックファイル（`requirements-audit.lock`）によるハッシュ検証を徹底しました。更新用ZIP展開環境など `requirements.lock` がない場合も、検証済みの同梱ロック情報（`src/dependency_lock.py` と `requirements.txt` の一致確認）から `requirements.lock` を復元したうえでハッシュ検証付きで導入します。
- `att user remove` と `att user student-id` サブコマンドを追加し、CLIからもユーザー削除（Keychain削除・確認プロンプト/`--yes`付き）と学籍番号変更（Keychainのパスワード引き継ぎ）を行えるようにしました。
- 更新の適用やロールバックの完了時に、使用中・待機中・復元用の記録から参照されなくなった古い専用仮想環境（`.updates/environments`）を自動削除し、ディスク容量の圧迫を防ぐようにしました。
- 手動更新などで現在版以下の古い更新待機データ（`.updates/pending`）が残っていた場合に、そのまま終了せず破棄して最新の更新確認・取得を行うようにしました。
- CI に macOS（`macos-latest`）上の実環境検証、依存ロックファイル（`requirements.txt` / `requirements.lock` / `src/dependency_lock.py`）の同期検証、および `gitleaks` によるシークレット検査を追加しました。
- 教室番号入力で全角数字（例: `６４２`、`７３１`）および7号館の4桁番号（例: `7301`）を受け付け、画面のQR番号入力欄でも4桁入力と全角数字入力に対応しました。
- `start.command` の起動を画面モード（`--ui`）に統一し、`README.md`・`COMMANDS.md` などの案内を揃えました。
- `config.json` が見つからない場合と `install.sh` でのリンク・`.venv` 不備時に、具体的な復旧コマンドを案内するようにしました。
- CLI 実行中の `Ctrl+C`・`Ctrl+D` を安全に捕捉し、トレースバックや誤った失敗ログを残さずに終了コード `130` / `1` で中断できるようにしました。
- TUI での操作失敗時に安全な失敗理由をログへ記録し、複数ユーザー並列処理時のログに匿名の対象番号（例: `対象=1/2`）を付けて追跡できるようにしました。
- すでにログイン済みで教室画面が開かれた場合は、重複していた再読み込みを行わないようにしました。
- 更新情報（`attendance-update.json`）と更新用アーカイブの ECDSA P-256 暗号署名・検証およびリリースの SLSA Build Provenance アテステーション付与に対応しました（外部依存の追加は不要です）。準備済みの更新やキャッシュ済み更新情報も現在の公開鍵設定に対して再検証します。
- 初回導入時および依存パッケージ準備時に Playwright のブラウザ取得元を上書きする環境変数を除外し、導入された Chromium の実体パスとピン留めリビジョンを検証するようにしました。
- 出席画面の遷移先検証で、HTTPSの標準ポート（443・ポート指定なし）以外へのリダイレクトや遷移を拒否するようにしました。
- `.updates/updater.log` と `.updates/dependencies.log` に256 KiBのサイズ上限と `.1` へのローテーションを導入し、`0o600` 権限とシンボリックリンク拒否を適用しました。
- ターミナルUIのメモリ上パスワード保持に300秒の有効期限を設け、期限切れ後やユーザー切替・画面終了・フォーム破棄／送信時にメモリから消去して必要時にKeychainから再取得するようにしました。
- `config.json` と `schedule.json` の読み書きを排他ロックで保護し、並行操作による設定の上書き消失を防ぐようにしました。
- 初回セットアップ時は macOS Keychain へのパスワード保存確認後に `config.json` を書き込む順序に統一し、入力中断時に未登録のユーザーが残らないようにしました。
- `config.json`・`schedule.json`・`logs/` の読み込み時にシンボリックリンクを拒否し、緩いファイル・ディレクトリ権限を `0o600` / `0o700` へ自動制限するとともに旧形式 `student_id` の形式検証を追加しました。
- 自動出席予定の保存・読込時に、有効な授業間で実際の登録時刻や受付時間（範囲指定または遅延許容25分）が重なる設定を検出し、競合する授業名と時間帯を表示して拒否するようにしました。
- UIで複数ユーザーを並列実行する際、セッションや認証状態を分離したまま単一の Chromium サーバープロセスを共有し、起動負荷と待ち時間を軽減しました。
- 大学側のエラーモーダル（`#errorModal`）やログイン失敗表示からメンテナンス・アカウントロック・セッション切れ・受付時間外などの定型原因を安全に判別し、任意本文や個人情報を記録せずに分かりやすい案内を表示するようにしました。
- GUIの既定ユーザー変更確認（U → D）と未保存確認で、変更前後のユーザー名・学生番号、現在の出席対象と保存済み選択の1人への切り替え、および自動実行（有効中／停止中）への影響を具体的に表示し、初期選択を「キャンセル」にしました。
- GUIの予定画面で自動実行を開始する際、開始前に既定ユーザー・次回実行日時と授業・適用期間・有効な予定件数を表示し、「開始する」「キャンセル」から明示的に確認できるようにしました（初期選択はキャンセル）。
- 有効な予定がない場合や適用期間が終了している場合、休講日等で期間内に実行可能な予定がない場合は理由を表示して開始を防止します。
- 開始確認画面を開いている間に既定ユーザーや実行条件が変更された場合は、そのまま開始せず新しい内容で再確認するようにしました。
- 一括出席の確認画面で、選択した全ユーザーの氏名・学籍番号・登録対象/対象外の人数と理由（出席済み、未履修、受付対象なし、確認失敗、授業情報不一致、確認のみモード）を確認でき、人数が多い場合も一覧をスクロールできるようにしました。
- 自動実行（`--scheduled`）で登録時刻の範囲指定がある予定でも、分境界をまたいだ直後（2分以内）の実行を取りこぼさないようにし、実行中の排他予約と完了を確認できた結果（`出席登録成功`・`出席済み`）のみの実行記録（`logs/schedule-runs.json`）によって確認実行（`--check` / `dry_run`）・送信前の失敗・履修登録なしや受付対象なしの結果で当日の本番実行を消費せず、同日の重複実行を防ぎます。
- 自動実行の LaunchAgent 設定に `logs/launchagent.log` へのログ出力先を追加し、アプリ起動前のエラーも安全な診断情報として記録するようにしました。
- 自動実行の登録（`launchctl bootstrap`）が失敗した際、以前の設定ファイルと登録状態の復元を試み、失敗内容を記録するようにしました。
- `att schedule status` で LaunchAgent と `schedule.json` の設定ずれ、ツールフォルダ移動時の旧登録パス、および自動実行の前提条件（`config.json`・`browser.headless`・既定ユーザー・Keychain パスワード・授業期間・有効授業数）を診断できるようにしました。
- `att schedule install` / `remove` で LaunchAgent が一致しない場合に、検出された `Label`・登録先パス・修復コマンドを案内するようにしました。
- TUI のメイン画面・予定画面から `L` キーで `logs/attendance-*.log`・`logs/launchagent.log`・`.updates/updater.log` の末尾を閲覧できるログビューアを追加しました。

## 利用者の操作

- `att update` で更新し、画面を開き直してください。
- 更新案内が出た場合は `att update --notes` で内容を確認し、`att update` で更新してください。手動コマンドはキャッシュの期限内でも最新情報を取得します。
- 更新確認を無効にする場合は、引き続き `ATTENDANCE_NO_UPDATE=1 att --ui` を使えます。通常起動ではアプリ本体や依存パッケージの自動更新は行いません。
- 新規セットアップやフォルダ移動後の再セットアップ時は、`requirements.lock` または検証済みの同梱ロック情報（`src/dependency_lock.py`・`requirements.txt` 等）を含む配布ファイル一式を用意した状態で `bash install.sh` を実行してください（有効なロック情報がない場合はエラーで停止します）。
- CLIでユーザーを削除する場合は `att user remove <ユーザー名>`（確認を省略する場合は `--yes` / `-y`）、学籍番号を変更する場合は `att user student-id <ユーザー名> <新しい学籍番号>` を利用できます。詳しくは `COMMANDS.md` を参照してください。
- 更新案内が出た場合は `att update --notes` で内容を確認し、`att update` で更新してください。手動コマンドはキャッシュの期限内でも最新情報を取得します。不要になった古い専用仮想環境は、更新や `att update --rollback` の完了時に自動で整理されます。
- 通常利用での追加操作は不要です。開発・PR作成時は依存関係を変更した際にロックファイルの同期を保ち、シークレットや個人設定を含めないでください。
- Finder から起動する場合は `start.command` をダブルクリックしてGUI（`--ui`）を開けます。CLIで実行する場合は引き続き `att` コマンドを使用してください。
- 教室番号には `642`・`731`・`7301` や全角数字をそのまま入力できます。`config.json` 不在や `install.sh` 失敗時は表示される復旧コマンドを実行してから再実行してください。
- CLI の入力や処理中に中断したい場合は `Ctrl+C` または `Ctrl+D` で終了できます。並列実行ログを確認する際は `logs/` 内の `対象=番号/総数` と `理由=...` を参照してください。
- 配布物のビルド来歴を手元で確認したい場合は、公開リリースから取得したファイルに対して `gh attestation verify attendance-update.zip --repo HR0101/AttendanceSystem` を実行できます。
- ターミナルUIを長時間開いたまま操作を再開した際にmacOS Keychainのアクセス確認が表示された場合は、許可（または「常に許可」）を選択してください。
- 手動で `schedule.json` を作成する場合は `COMMANDS.md` の手順どおり `chmod 600 schedule.json` を実行してください（緩い権限のファイルは読み込み時に自動制限されます）。
- 旧形式の `config.json` に空白や記号を含む `student_id` を設定している場合は、半角英数字へ修正してから実行してください。
- 自動出席の予定追加・編集・有効化時に受付時間の重複エラーが出た場合は、表示された授業名と時間帯を確認し、登録時刻や有効／無効を調整してください。
- 複数ユーザー一括確認・登録やエラー表示時の操作手順に変更はありません。エラー表示でメンテナンスやアカウントロック等が案内された場合は大学側の案内・設定を確認してください。
- GUIで既定ユーザーを切り替える際は、U → D で影響内容を確認したうえで、Tab または ←→ で「切り替える」を選んで Enter を押してください（初期選択の「キャンセル」で Enter を押すと変更せず戻ります）。
- GUIの予定画面（`S`）で `I` を押して自動実行を開始する際は、表示されたユーザーと次回予定を確認し、`Tab`/`←→` で「開始する」を選んで `Enter` で確定してください（`Esc`/`Q` または初期選択の「キャンセル」で変更せず戻ります）。
- 一括出席の確認画面で人数が多い場合は `↑`/`↓`/`PgUp`/`PgDn` で全対象者と対象外の理由を確認し、`Tab`/`←`/`→` と `Enter` で「戻る」または「出席登録」を選んでください（初期選択は「戻る」です）。
- 自動実行を利用中の場合は、更新後に `att schedule install`（または GUI の予定画面で `I` を押して停止→開始）を実行すると最新のログ出力設定が反映されます。
- 自動実行で失敗した場合は `logs/attendance-*.log` とあわせて `logs/launchagent.log` を確認してください（共有時は個人・機微情報を含めないようご注意ください）。
- 自動実行の状態や前提条件を確認するには `att schedule status` を実行し、設定ずれが出た場合は `att schedule install` で反映してください。
- フォルダ移動などで旧 LaunchAgent の残存が報告された場合は、案内に表示される `launchctl bootout` / `rm` コマンドを実行してから `att schedule install` を実行してください。
- ターミナル画面で直近のログを確認する場合は `L` キーを押し、`Tab` / `1`～`3` でログ種別を切り替え、`↑↓` / `PgUp` / `PgDn` で移動してください（`Esc` / `Q` で戻ります）。
