# v0.2.8

## 変更内容

- 通常起動の更新確認をバックグラウンドで実行し、GitHubやDNSの応答待ちで出席操作の開始・終了を遅らせないようにしました。
- 成功した更新情報は原則24時間再利用します。通信失敗時や利用制限時は従来の再試行間隔を維持します。
- UIを開く直前の通知出力をやめ、起動後に確認が完了した場合も画面内の更新案内へ反映します。
- CLIの入力中には通知を割り込ませず、起動時の保存済み情報と処理終了時に取得済みの新情報を案内します。
- `att schedule status` で LaunchAgent と `schedule.json` の設定ずれ、ツールフォルダ移動時の旧登録パス、および自動実行の前提条件（`config.json`・`browser.headless`・既定ユーザー・Keychain パスワード・授業期間・有効授業数）を診断できるようにしました。
- `att schedule install` / `remove` で LaunchAgent が一致しない場合に、検出された `Label`・登録先パス・修復コマンドを案内するようにしました。
- TUI のメイン画面・予定画面から `L` キーで `logs/attendance-*.log`・`logs/launchagent.log`・`.updates/updater.log` の末尾を閲覧できるログビューアを追加しました。

## 利用者の操作

- `att update` で更新し、画面を開き直してください。
- 更新案内が出た場合は `att update --notes` で内容を確認し、`att update` で更新してください。手動コマンドはキャッシュの期限内でも最新情報を取得します。
- 更新確認を無効にする場合は、引き続き `ATTENDANCE_NO_UPDATE=1 att --ui` を使えます。通常起動ではアプリ本体や依存パッケージの自動更新は行いません。
- 自動実行の状態や前提条件を確認するには `att schedule status` を実行し、設定ずれが出た場合は `att schedule install` で反映してください。
- フォルダ移動などで旧 LaunchAgent の残存が報告された場合は、案内に表示される `launchctl bootout` / `rm` コマンドを実行してから `att schedule install` を実行してください。
- ターミナル画面で直近のログを確認する場合は `L` キーを押し、`Tab` / `1`～`3` でログ種別を切り替え、`↑↓` / `PgUp` / `PgDn` で移動してください（`Esc` / `Q` で戻ります）。
