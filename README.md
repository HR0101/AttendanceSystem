# 出席ツール

macOS で、本人が受講する授業の出席画面を確認し、出席登録を行う Python ツールです。大学・授業の規則で自動化が許可されている場合に利用してください。追加認証や想定外の画面が現れた場合は停止します。

## 動作環境

- macOS、Python 3.10 以降
- zsh または bash（自動セットアップ対応）
- インターネット接続と対象大学の出席システムを利用できるアカウント
- 初回セットアップ用のターミナル

GUIはターミナル内で動作します。幅62文字・高さ24行以上が必要で、幅106文字以上では操作ガイドと今回の操作履歴も表示します。白背景のターミナルで見づらい場合や色を使わない場合は、`ATTENDANCE_UI_THEME=light` や `NO_COLOR=1` を指定して起動できます（詳しくは[コマンド・操作早見表](COMMANDS.md#attendance)を参照）。

## 使い方

### ダウンロード・初回セットアップ

Python 3.10以降を用意し、次のコマンドで取得・セットアップします。

```sh
git clone https://github.com/HR0101/AttendanceSystem.git
cd AttendanceSystem
bash install.sh
```

ZIPで取得する場合は、[GitHubリポジトリ](https://github.com/HR0101/AttendanceSystem)の「Code → Download ZIP」からダウンロード・展開し、フォルダ内の [install.command](install.command) をダブルクリックしてください。展開したフォルダで `bash install.sh` を実行する方法も使えます。

セットアップは仮想環境・依存ライブラリ・Chromiumを導入し、初回のみ `config.json` を作成します。`att` コマンドの登録とPATH設定も自動で行うため、エイリアスやPATHを手動で設定する必要はありません。管理者権限は不要で、既存の設定ファイルや同名の別コマンドは上書きしません。

### セットアップ後の起動

新しいターミナルを開き、次を実行してください。`att` はどのフォルダからでも使えます。

```sh
att user add             # 自分の認証情報を登録
att --ui                 # GUIを開く
att --check 642          # 指定教室の出席状態を確認（登録しない）
```

Finder からフォルダ内の [start.command](start.command) をダブルクリックして GUI（`--ui`）を起動することもできます。

今のターミナルですぐ使いたい場合や `att: command not found` が出る場合は、セットアップ完了時に表示される `source` コマンドを実行してください。通常のzsh環境では `source ~/.zshrc`、bashでは `source ~/.bash_profile` です。

セットアップは `~/.local/bin/att` にリンクを作り、zshでは `~/.zshrc`（`ZDOTDIR` 設定時はその配下）、bashでは `~/.bash_profile` にPATH設定を追加します。ダウンロードしたフォルダは削除・移動せず保管してください。移動する場合は `~/.local/bin/att` のリンクだけを削除し、移動先で `bash install.sh` を再実行してください。

### 更新通知と手動アップデート

v0.2.8以降は、通常起動時にGitHubの正式リリースの `attendance-update.json` をバックグラウンドで確認します。確認結果は原則24時間再利用し、通信の完了を待たずに出席画面や処理を開始します。新しい版がある場合に次の案内を表示するので、更新内容を見て、更新したい時に `att update` を実行してください。通常起動でZIPの取得やアプリ本体の適用は行いません。

`--ui` では起動前の通知出力を行わず、画面内に案内を表示します。起動後に確認が完了した場合も画面へ反映します。CLIでは保存済みの情報を起動時に表示し、処理中に新情報を取得できた場合は終了時に案内します。確認が終わらなくても、終了を待たせることはありません。

```text
アップデートがあります: v0.2.4（現在 0.2.3）
  更新内容を確認: att update --notes
  アップデートする: att update
```

更新がなければ通知を表示しません。通信失敗も出席処理を妨げずログに残し、通常は1時間後、利用制限ではサーバー指定の解除時刻以降に再確認します。GitHub APIは使わず、ETag・304によって検証済みJSONを再利用します。

Git・ZIPのどちらで導入した場合も同じ仕組みです。`config.json`、`schedule.json`、Keychainのパスワード、ログ、ブラウザの保存データ、`.venv`、`.git` は保持します。自動実行（`--scheduled`）・デモ・ヘルプ・バージョン表示・ユーザーや予定の管理では更新通知の確認を行いません。他の出席処理が動いている時に `att update` を実行した場合は準備状態で待機し、その処理の終了後にもう一度 `att update` で適用します。

```sh
att update               # 今すぐ確認・取得し、他の処理がなければ適用
att update --notes       # 公開版の更新内容を表示（取得・適用なし）
att --version            # 現在のバージョン
att update --rollback    # 直前の更新前の版へ戻す
```

`att update` は更新情報JSONの版番号・ZIPサイズ・SHA-256（および公開鍵設定時は ECDSA P-256 署名）と、更新用ZIPの実サイズ・SHA-256・ファイル構成・Python構文・起動を確認してから適用します。JSONとZIPが食い違う場合や署名が不正な場合は適用しません。取得時のリダイレクトもHTTPSのGitHub配布用ホストだけに限定します。また、GitHub Releases の公開成果物には SLSA Build Provenance アテステーションが付与され、`gh attestation verify attendance-update.zip --repo HR0101/AttendanceSystem` でビルド来歴を検証できます。適用中に失敗した場合は元に戻し、途中でプロセスが終了した場合は次回起動時に復元します。通常起動や `--notes` では、すでに準備された更新も適用しません。

v0.2.3以降は、`att update` で依存パッケージが変わる更新も自動で準備します。配布元が固定した版・SHA-256のパッケージと対応するChromiumを専用の仮想環境へダウンロードし、Playwright の取得元上書き環境変数を除外したうえで、ピン留めされた Chromium リビジョン・配置先・整合性・ブラウザ起動を確認してから、アプリ本体と一緒に切り替えます。準備に失敗した場合は現在のアプリと実行環境を維持します。ロールバックでは依存環境も戻します。元の `.venv` は保持します。

初回の移行後も、通常起動は既存の `.venv` を利用します。専用環境の準備は最初の `att update` で行い、そのダウンロード中はインターネット接続が必要です。ヘルプ・バージョン表示・デモ・`update --notes`・`update --rollback` は準備なしで利用できます。依存関係の記録は `.updates/dependencies.log`、更新確認の失敗は `.updates/updater.log` に保存します。更新の確認・通知を止める場合は `ATTENDANCE_NO_UPDATE=1 att --ui` を使ってください。

**この機能を含まない旧版の利用者は、初回だけ手動更新が必要です。** Gitの場合はインストール先で `git pull --ff-only`。ZIPの場合は最新版の `src/`、`main.py`、起動スクリプトを既存の同名ファイルへ反映します。`config.json` と `schedule.json` は上書きしないでください。

**v0.2.1以前でAPIの403が出る場合も、v0.2.2以降への初回移行だけ手動更新が必要です。** Gitで導入した場合は、そのフォルダで `git pull --ff-only` を実行してください。ZIPで導入した場合は、GitHubの「Code → Download ZIP」で最新版を取得して別フォルダに展開し、`src/`、`main.py`、起動スクリプトを既存フォルダへ反映してください。個人設定は上書きしません。旧版で `att update` が使える回線なら、その操作でも移行できます。移行後は学内回線でも新しいJSON経路で確認します。

更新結果は `更新なし:`、`更新失敗:`、`更新待機:` を区別して表示します。更新なしの場合は現在版と公開版、失敗の場合は通信・アクセス制限・配布データなどの原因を表示します。最新リリースにJSONが添付されていない場合は、更新の確認失敗として表示します。`att update` の終了コードは、確認成功・更新なしが0、失敗・待機が1です。

通信失敗はHTTPステータス、DNS、HTTPS証明書、TLS、タイムアウト、受信中の切断を区別して表示します。403/429で利用制限のヘッダーがある場合は、通常のアクセス拒否と区別し、`X-RateLimit-Reset` / `Retry-After` に基づく再試行時刻を表示します。

### 更新を配布する側の手順

`src/version.py` の `VERSION` と同じ版の `updates/X.Y.Z.md` に「変更内容」「利用者の操作」を記載します。CIはファイルの欠落・版不一致・空欄・未記入の目印を拒否します。PRでは変更に合わせてこのファイルも作成・追記してください。既存ファイルを変更せずコードだけ変えたPRもCIで失敗します（[記載例](updates/0.2.3.md)）。

`python3 scripts/check_update_notes.py` で確認し、変更をGitHubへ反映して、その版と一致する `vX.Y.Z` タグをpushしてください。`.github/workflows/release.yml` が全テストを実行し、個人設定を含まない `attendance-update.zip` と、版番号・サイズ・SHA-256・更新内容を記載した `attendance-update.json` を作成し、GitHub Artifact Attestations でビルド来歴を付与します。`secrets.RELEASE_SIGNING_KEY`（またはローカル実行時の `--signing-key` / `RELEASE_SIGNING_KEY_FILE`）が設定されている場合は ECDSA P-256 署名（JSON 内 `signature` と `attendance-update.zip.sig`）も生成します。MarkdownはGitHub Releaseの説明にも使います。アセットをドラフトに添付してから正式リリースとして公開するため、利用者はそろった配布データを取得できます。通常のコミットをpushするだけでは更新を配信しません。

リリース用のワークフローは、テスト（依存ライブラリを導入し、読み取り権限のみ）と公開（外部パッケージを導入せず、書き込み権限あり）を別のジョブに分けています。依存ライブラリを変更する場合は `requirements.lock` と配布用の `src/dependency_lock.py` を再生成してください（[手順](COMMANDS.md#tests)）。ロック情報はPythonのデータファイルとしてZIPに同梱します。旧版の自動更新が未知の `.lock` ファイルを拒否するため、`requirements.lock` 自体はZIPに追加しません。ビルド時に両方の内容が一致するか検証します。v0.2.2以前から最初に移行するリリースでは `requirements.txt` を変更しないでください。v0.2.3への移行後は、依存変更も `att update` で取得・適用できます。

ローカルで配布内容だけ確認する場合は `python3 scripts/build_release.py v0.2.8` を実行します。生成先は `dist/attendance-update.zip` と `dist/attendance-update.json` です。GitHubへのpushやリリース公開はこのコマンドでは行いません。

## 設定ファイル

初回起動時に学生番号・ユーザーネーム・パスワードを入力します。学生番号とユーザーネームはローカルの `config.json`、パスワードは macOS Keychain の `UniversityAttendanceTool` に保存します。これらはGitの追跡対象外です。`config.json` を共有したり、ログを公開したりしないでください。

ユーザーネームは表示・選択用で、大学へのログインには学生番号を使います。名前と学生番号の重複登録はできません。既存の `student_id` 設定も利用でき、初めは学生番号をユーザーネームとして扱います。

画面の `U` でユーザー管理を開き、`I` で学籍番号変更、`X` で確認後の削除ができます。CLIでも `att user student-id`・`att user remove` で同様に操作できます。番号変更では保存パスワードを引き継ぎ、削除では保存パスワードも取り除きます。詳しくは[ユーザー管理の操作](COMMANDS.md#users)を参照してください。

GUIで複数ユーザーを選んでEnterを押すと保存し、次回も同じ選択を復元します。既定ユーザーは通常コマンド・自動出席用として別に管理します。パスワード入力はF2またはCtrl+Tで表示を切り替えられ、各入力欄は←→・Home/Endで移動して途中から編集し、Ctrl+Sで途中からでも保存できます。

GUIのU → D（初期選択はキャンセル、Tab → Enterで確定）で既定を変更した場合は、変更前後の既定ユーザー、出席対象の1人への絞り込み、自動実行の状態と対象を確認したうえで、その画面の出席対象も選んだ1人へ即時に切り替えます。以前の授業情報は破棄して再確認するため、画面を閉じ直す必要はありません。

未保存の入力・選択を残して戻る場合は、保存・破棄・編集継続の確認が出ます。ユーザー一覧や確認画面はEsc/Q、入力フォームはEscで戻ります。保存に失敗した場合も入力内容を保持します。

GUIでは `U` で一覧を開き、↑↓とSpaceで出席するユーザーを複数選択してEnterで保存・適用できます。次回も同じ選択を復元します。QR番号の授業をユーザーごとに確認し、「○人を出席登録」からまとめて登録します。処理は最大4人ずつ並行して行い、結果は `U` → `V` で個別に確認できます。

大学側でパスワードを変更した場合は、`att user password ユーザー名` で保存パスワードを更新できます。ユーザー名を省略すると既定ユーザーが対象です。GUIでは `U` → 対象ユーザーを選択 → `P` から、新しいパスワードを確認用と合わせて2回入力します。大学側のパスワード自体は変更せず、Keychainの保存内容だけを更新します。GUIで使用中のユーザーの変更は、その画面にも即時反映されます。起動中の別画面は再起動するかユーザーを選び直してください。

`config.json` の `dry_run` を `true` にすると確認のみになります。初期値は `false` です。`browser.headless` は初期値が `true` で、`false` にするとブラウザを表示します。自動実行には `true` が必要です。

### 教室番号

入力番号はQRの出席URL用の番号です。`642` は `/attendance/class_room/642` に、7号館の `731` は `/attendance/class_room/7301` に変換します。全角数字（例: `６４２`、`７３１`）や、7号館の4桁番号（例: `7301` → 教室 `731` / URL `7301`）もそのまま入力できます。QR番号と授業情報の教室名は異なる場合があります。例えばQRのURLが `/attendance/class_room/435`、授業教室が432の場合も `435` を指定してください。GUIでは入力値を「QR番号」、大学側の表示を「教室名」として表示します。

### 自動実行の予定

予定は `schedule.json` に保存します。[schedule.example.json](schedule.example.json)をひな形にしてJSONを編集するか、GUIで授業ごとに設定できます。

| 項目 | 内容 |
| --- | --- |
| `active_from` / `active_until` | 授業期間（YYYY-MM-DD） |
| `blackout_dates` | 休講日の配列（YYYY-MM-DD） |
| `courses` | 授業設定の配列 |
| `weekday` | 授業の曜日（mon～sun） |
| `start_time` | 大学の画面と照合する授業開始時刻（HH:MM） |
| `room` | QR用の教室番号 |
| `course_name` | 大学の出席画面と一致する授業名 |
| `register_time` | 登録時刻。範囲指定時は範囲開始（HH:MM） |
| `register_until` | 範囲終了（HH:MM）。省略・空欄なら固定時刻 |
| `enabled` | 授業ごとの有効／無効。省略時はtrue |

登録時刻と範囲終了を両方省略・空欄にすると、授業開始5分後に実行します。範囲指定の入力例は[コマンド・操作早見表](COMMANDS.md#schedule)を参照してください。

## 自動実行について

自動実行はmacOSのユーザー用LaunchAgentを使い、既定ユーザーで行います。GUIで複数のユーザーを選択しても、自動実行のユーザーは変わりません。GUIを閉じても動作しますが、Macの終了中は動きません。事前に一度手動でログインし、Keychainにパスワードを保存してください。

固定時刻のみの予定では、スリープ復帰等による遅延は登録予定時刻から25分まで受け付けます。範囲指定を含む予定では範囲内の各分に確認し、選んだ登録時刻（分境界またぎの2分以内の遅延を含む）で1日1回だけ出席処理を行います。この場合、固定時刻の予定も含めて大幅な遅延分の出席は行いません。登録時刻にMacを起動・ログイン・スリープ解除しておいてください。

設定した学期外・休講日は対象外です。指定した出席URL、授業名、開始時刻を確認できない場合は停止します。自動実行の同日重複防止には `logs/schedule-runs.json`、LaunchAgent の標準出力・エラーや起動前エラーには `logs/launchagent.log` を使います。

## 判定とログ

すでに出席済みの場合は再登録しません。履修未登録の警告や受付対象なしの表示があれば、出席ボタンを押さずに結果を表示します。「現在、出席できる授業はありません。」という表示だけでは、時間外か授業がないかは判定できません。登録後も出席済み表示を確認します。結果はターミナルとローカルの `logs/`（`logs/attendance-*.log` および自動実行時の `logs/launchagent.log`）に記録します。

GUIでは授業情報の取得時に登録せず、画面で登録するときにユーザーごとに再度授業を照合します。出席済み・履修未登録・受付対象なし・確認失敗・授業情報が他の人と異なるユーザーは登録対象から外れます。一部が失敗しても他のユーザーの処理は続きます。`dry_run` が有効な場合は全員の登録を無効にします。

大学側でURLや画面が変更された場合、公式画面を確認して `config.json` を更新してください。`login_url` と `top_url` には同じホスト名を指定します。
